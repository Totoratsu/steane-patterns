Limits and what next

The simulator has hard limits and one approximate model. You will be able to say which results to trust, which to treat with care, and where the project could go.

Key terms

Backend
Mid-circuit measurement
Statevector

What the simulator cannot do

Each limit below comes from a line in the repository, not from a general statement about quantum computers. A backend is the machine or simulator that runs the circuits; the page asks it to measure and reset a single ancilla after each check, many times in one circuit.

No IonQ backends. The function _backend_problem in engine/bridge.py refuses any backend whose name contains "ionq" or whose operation list lacks reset. IonQ documents mid-circuit measurement as supported on some targets and not others, and single-qubit reset as supported. The IonQ simulator supports it, and the qiskit-ionq provider says QPU support is rolling out. This project has not been run on IonQ, so it refuses every IonQ backend until a target is confirmed; this is our caution, not an IonQ limit. Without the reuse, two Steane blocks with fresh ancillas for the 12 checks would need 26 qubits, more than the 24 that Qiskit’s BasicSimulator allows for a statevector. The page shows the message and asks for the built-in Qiskit simulator.

Caps on rounds and shots. MAX_ROUNDS is 5 and MAX_SHOTS is 256, and the noise strength must be between 0 and 0.1, or the run is refused with an error. Rounds and shots above the caps are clamped to them. The reason is cost: the simulation is a full statevector, run shot by shot, because the circuits contain mid-circuit measurements. The README gives the defaults, 3 rounds and 48 shots, as taking a few seconds natively and more in the browser.

Logical gates only before encoding. Your gates act on the two input qubits, then each qubit is encoded. Preparation is not fault-tolerant: noise starts after encoding. Gates between rounds would need the decoder model to track errors moving between the two blocks. As built, the two blocks are decoded independently.

Where the model is approximate

The decoders work on a phenomenological model: data errors between rounds and measurement errors, one Pauli type per block. For SI1000 it is a rough fit. The circuit-level noise, the 2-qubit depolarizing after each CX and the hook errors that spread through those gates, is not in the decoders' model. The priors for SI1000 are for data errors and for measurement errors, a fit, not a derivation. That is why Chapter 10 shows no optimal-decoder limit for it. A real decoder with an imperfect noise model faces the same situation.

Idle noise in SI1000 is charged once per round, as if the 12 checks ran in parallel on 12 ancillas. Reusing one ancilla is only a way to stay within the qubit limit.

What next

Three directions follow from what the chapters already showed.

Bigger codes. On the Steane code Relay-BP sits within a few percent of the optimal decoder, so there is little room left to improve it. We expect Relay-BP to pull further ahead of BP on large qLDPC codes, where BP's trapping sets hurt more. The official relay-bp package is written in Rust and cannot be installed in the browser, which is why this project has its own numpy version.

Joint decoding. The page decodes X and Z separately. Chapter 10 explains why a joint decoder that uses Y correlations can beat the separate limit under depolarizing noise.

An exact circuit-level model. A detector error model derived from the circuit itself, hook errors included, would make a limit for SI1000 meaningful. This is the missing piece for an exact SI1000 limit.

To go on from here, Appendix B shows how to run the simulator and python -m engine.selfcheck yourself, and Appendix C lists the papers: the Relay-BP paper (Müller et al., arXiv:2506.01779) and the honeycomb-memory paper that defines the SI1000 noise model.

Try it in the simulator

Run SI1000 at p = 0.01 with the maximum 5 rounds and 256 shots. Look for the Optimal decoder (limit) bar: it is absent. Then switch to depolarizing at the same p and watch it appear.

Check yourself

Why does an IonQ backend get a message instead of a run?

Repeated rounds with one reused ancilla need mid-circuit measurement and reset, which IonQ documents for some targets only. The project has not been run on IonQ, so it refuses those backends as a precaution.

What are the largest numbers of rounds and shots the page accepts?

5 rounds and 256 shots; larger requests are clamped.

Why can’t the limit be shown for SI1000?

Its decoder priors are approximate and hook errors are not modelled, so an exact limit would describe a different model.
